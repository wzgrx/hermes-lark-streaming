# 0.20.2：历史账本与后台采样增强

日期：2026-10-03。范围：Card 的账本和只读遥测，不改变 V1 设计或 Hermes 的推理/认证/会话机制。

## 已复现并修复

| 问题 | 根因 | 修复与验收 |
|---|---|---|
| 已知零用量被写成未知；后到的零值纠正保留旧非零值 | `value or None` 丢掉 `0`，SQL `COALESCE` 又保留旧值 | 保留解析器输出的 `0`/`None` 区别；缓存读、缓存写、思考三组参数化回归 |
| 期间总量和模型表可能来自不同时间点 | 多个 SELECT 没有共享显式事务 | 只读 `BEGIN` 固定快照；在首查询后注入真实 WAL 写入，确认本次报告旧快照一致、后续报告看见新记录 |
| 慢查询/采样占位提前释放，下一次请求可能重复启动线程 | 取消 `asyncio.to_thread` 的等待并不停止正在执行的线程 | 保留后台任务直到读取实际结束；后续请求合并；调用者仍有等待预算，不启动第二个写卡任务 |
| 终态等待超时仍展示旧缓存为刷新成功 | 等待超时被静默跳过 | 终态历史显示 unavailable；线程保持所有权，完成后供后续轮次使用 |
| 调用者可修改嵌套历史缓存 | `dict()` 仅复制顶层 | 深拷贝小型有界摘要；模型表与统计字典隔离 |

SQLite 仍以 `mode=ro` 打开，0.2 秒锁等待和 0.5 秒 SQL progress deadline 保留；不 checkpoint、不迁移生产数据库。历史 finish 的两次等待各最多 0.8 秒；既有读取超时直接返回 unavailable，不再次等待同一任务。资源 finish 最多等待 2 秒，NVIDIA 子进程的原有 1 秒超时与清理保持不变。调用者取消等待不取消共享读任务。

线程占位修正遵循 [Python asyncio 的等待取消与 shield 语义](https://docs.python.org/3.11/library/asyncio-task.html#shielding-from-cancellation)。后台只读线程和 CardKit 写卡控制器仍是不同职责；没有新增推理客户端或持续设备监控。

## 性能与验证边界

- 历史 SQL 从五个 SELECT 降至两个：期间汇总和前三组模型表。其核心收益是同一快照和减少重复查询，不保证所有数据分布都更快。
- 使用临时目录的 60,000 条纯合成记录，升级前后报告完全相同。该轮中位数：旧 48.477 ms，新 49.853 ms；不将其写成加速结论。
- 十五项新回归涵盖上述情况、空期间真实零/缺失用量 unknown、读线程合并、等待预算及取消等待。初始十一例中十例在旧源码失败。
- 1450 项本地全量测试、Ruff 与 mypy 通过；GitHub exact-revision CI 另查，不把本地测试写成线上验收。
