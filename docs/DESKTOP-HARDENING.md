# 0.20.4 桌面 V1 修复与验证

日期：2026-10-03。范围：桌面飞书、当前 Card 项目。手机按用户要求排除；不重做 V1，不引入第二个 SDK/Gateway，不升级 Hermes 核心或 LCM。

## 本轮修复

| 问题 | 修复与边界 |
|---|---|
| 工具隐藏后打开，更新不存在的面板，阻塞流式正文 | 跟踪服务端已接受的面板集合；显式添加/删除，工具始终位于正文之前；成功后才提交集合与 sequence |
| 服务器缺失工具/资源面板，反复更新同一 ID | 复用一次性整卡重建与正文重放；再次失败转既有失败处理，避免无限循环 |
| 0.20.3 时区缓存失效已修，但配置文件入口仍是旧快照 | 用真实 YAML 修改＋UTC/上海跨日跨月 SQLite 回归验证；同一控制器感知新时区 |
| 半写入/错误类型的配置打断回调 | 保留最后有效配置，日志限频且不输出 YAML 原文；修好文件后自动恢复 |
| 第一次 API 失败后，“首响应”一直缺失 | 从最早 API 请求起算至最早已观测首块，包括重试/等待；不是消息到达或客户端绘制时间 |
| 历史等待、读取失败、没有记录看起来一样 | 三种状态分别一行显示，不用多行横杠假装有统计；已知零值仍正常显示 |
| 原始记录/较早省略标签不准确 | 改为有界“步骤摘要”和“组未展示”；不声称截断的摘录是完整日志 |
| 资源单位与范围含糊 | 二进制内存标记 GiB；只有 WSL 采样标为 WSL，其余显示主机内存 |
| V1 依赖另一布局第 N 个元素 | 提取共享模型身份/遥测说明函数，去掉位置索引耦合 |

原有面板使用局部更新，不发送 expanded 重置。首次新增面板仍默认折叠；恢复用整卡重建会重置面板视图，这是应急路径，不承诺保留客户端本地状态。网络超时的接收结果不明确时，仍执行原有保守重试策略，不为了正文继续而冒险跳过 sequence 一致性。

- 有效空配置是显式恢复默认值；错误 YAML/类型和临时缺文件才保留上一快照。

- 费用与账号额度仍需可靠来源；本机用量不等于供应商账单。
