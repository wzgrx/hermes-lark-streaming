## 既有能力与持续门禁

| 能力 | 当前证据 | 门禁 |
|---|---|---|
| 原生 observer + AST | 注册/兼容/补丁往返测试 | AST 仍是投递 owner，尚未完全移除补丁 |
| doctor / metrics / monitor | 进程识别、错误指标、旧快照识别 | 指标不冒充客户端视觉结果 |
| 投递三态、sequence/UUID、恢复 | 自动回归、部分真实 CardKit API 验证 | 未确认回执保留 unknown，控制重复发送 |
| 背压、续卡、历史收缩 | 已有实现与回归 | 长任务真实矩阵；区分卡片收缩与模型压缩 |
| profile/bot、审批/clarify、锚点 | 已有隔离与身份测试 | 单 resolver/owner，逐场景真实复验 |
| 表格/Markdown/图片/中断 | 已有转换、分片与恢复测试 | 特殊内容/客户端版本样本验收 |
| CLI smoke / 可选 sidecar | 工具与可选进程模式已实现 | 不作为必需环境，不新开第二条连接 |
| 供应链 | 固定 Actions SHA、CodeQL、发布工作流 | 某版发布/签名/SBOM 以真实产物为准，不凭工作流打勾 |
| 国际化/可访问性 | 已有 locale 与状态文字 | 手机/主题/可访问性矩阵需独立证据 |

## 暂不扩张的架构

- 保留 Python lark-oapi 链路；Node SDK/Channel SDK 是评估选项，不是外观修复前提。
- 等 Hermes 稳定 renderer claim/suppress API 和完整路由载荷，再一次性迁移 owner。
- 传输迁移前须通过锚点、重试去重、媒体、审批、Cron、打断和多 bot 的真实对比。
- 不并行启用 observer、AST 与第二个 Channel sender 投递同一回复。
