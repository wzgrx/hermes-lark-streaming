# 0.20.22 — 整卡压缩后的代码展示 / current-runtime acceptance

## 范围与原因

- 0.20.21 修复了单元素 Markdown 分块，但整张卡片超过字节/元素预算后，`card_limits.py` 仍直接切取字符串尾部。切点落在代码中时会丢失开头围栏，只留下代码尾部和结束围栏，代码被误显示为普通正文。
- 本轮把普通压缩、最小卡片重建、最后一次缩减统一接入围栏感知的尾部展示。省略提示放在代码外；保留正常语言标记；已闭合及未闭合源代码都使用闭合的最终展示围栏。保留下来的代码正文字符保持原样，不把省略提示冒充源代码。
- 遇到异常长的语言/围栏元数据，优先有界展示代码尾部，省去超预算元数据。内嵌相同字符围栏会增长展示围栏，避免截断点把字面内容变成结束围栏。不是完整 CommonMark/嵌套列表解析器。
- 源对象不变；最新回答优先；28 KB、200 元素、2400 字符分块策略及 V1 原生布局不变。压缩仍有明确省略提示，不声称完整保存所有卡片内容。源会话、数据库和投递策略不变。

## 本地环境决策

- 用户要求只使用正在运行的 Hermes。本轮唯一的本地宿主源码是 `/home/wzgrx/.hermes/hermes-agent`，当前提交 `0764e9165721fdec30a11cf5fb0ac255cb09bb6f`；不克隆/建立新的官方源码快照，也不运行第二个 Gateway。

- 当前依赖中存在同名 `tests` 包，导致跨测试模块导入串包；新增本地 `tests/__init__.py` 明确归属。
